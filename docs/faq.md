# 常见问题

中文项目被问得最多的几类问题。把它当成"重复 issue 的沉淀池"，
被问到第二次就写进来。

## 关于这个模板

### 为什么不用默认的 VitePress 主题？

可以直接用，但默认主题是按英文排版调优的：

| 问题 | 默认表现 | 本模板的处理 |
| --- | --- | --- |
| 中文行高偏紧 | `1.5` 左右 | 调到 `1.75` |
| 中西文黏连 | 无间隙 | `text-spacing-trim` 自动加 1/4 字宽 |
| 容器标题是英文 | `TIP` / `WARNING` | 改成"提示" / "注意" |
| 界面文案是英文 | Search / Prev / Next | 全部中文化 |
| 本地搜索 | 需自行配置 | 已配好中文分词 |
| 表格溢出 | 需手动处理 | 已允许单元格换行 |

### 模板会不会太重？

不会。**没有引入任何额外依赖**，只用了 VitePress 自带能力：

- `package.json` 里只有 `vitepress` 一个依赖
- 主题是 `extends DefaultTheme`，不是重写
- 排版改动集中在一个 CSS 文件，删掉即恢复原样

### 怎么删掉不需要的示例页面？

1. 删掉 `docs/` 下对应的 `.md` 文件
2. **同步删掉 `config.mts` 里侧边栏和导航的对应条目**

只做第一步会留下死链，`pnpm build` 会直接报错（这是模板有意开启的检查）。

## 关于部署

### 部署后样式全丢、链接 404？

`base` 配置和实际部署路径不一致。对照表见[部署说明](/guide/deployment#步骤一确认-base-路径)。

本地用 `pnpm preview` 可以提前复现：

```bash
pnpm build
pnpm preview
```

### Actions 里构建成功但页面是 404？

Pages 的 Source 必须选 **GitHub Actions**，不能选 "Deploy from a branch"。

### 私有仓库能部署 Pages 吗？

可以，但 GitHub Pages 的可见性跟仓库一致，且需要相应套餐支持。
公开文档站建议直接开公开仓库。

### 推送后多久生效？

首次约 1～2 分钟，之后增量构建更快。如果超过 5 分钟没变化，去 Actions 标签页看日志。

## 关于写作

### 中西文之间的空格必须手动加吗？

模板用 CSS 加了自动间距作为兜底，但**并非所有浏览器都支持**。
正文里仍建议手动加空格，这是目前最稳妥的做法。

### 文档要不要中英双语？

除非有稳定的英文贡献者，否则**不建议**。半成品英文站比只有中文更伤信任，
而且中文文档更新后英文不同步会产生误导。

### 中文标题生成的锚点可靠吗？

大部分情况可靠，但不同渲染器对中文标点和大小写的处理有差异。
跨页引用锚点前，用 `pnpm build` 验证一次。

### 需要写更新日志吗？

需要，但不用写得像发布说明那么正式。`docs/changelog.md` 里按版本列
"新增 / 变更 / 修复"三类即可，**关键是让读者知道升级会不会破坏现有用法**。

## 关于维护

### 怎么让文档不被改坏？

模板已开启两项自动检查：

1. **死链检测**（`ignoreDeadLinks: false`）：构建时检查内部链接
2. 建议再加**术语检查**：见[进阶定制 · 文档质量 CI](/guide/customize#七加文档质量-ci)

### 文档目录越来越乱怎么办？

按**读者的使用路径**重组，不要按代码模块。判断标准：

> 读者带着一个问题来，能不能在三层点击内找到答案？

找不到，就是结构问题，不是搜索问题。

### 有人提 PR 改错别字，接受吗？

接受。`editLink` 就是为了降低这个门槛而配的。
改动再小也是贡献，在 `changelog` 里致谢即可。
