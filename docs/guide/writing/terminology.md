# 术语与用词

中文技术文档最大的敌人不是错别字，是**同一个东西在三页里有三种叫法**。
这份表用来统一整个文档站的口径。

## 一、建立你的术语表

开一个 `docs/glossary.md`，或在项目根目录维护 `TERMS.md`，格式如下：

| 术语 | 统一用法 | 禁止用法 | 首次出现时的解释 |
| --- | --- | --- | --- |
| 配置项 | 配置项 | 参数、选项、字段 | 指 config.mts 中的键 |
| 构建 | 构建 | 编译、打包（除非确指） | 生成静态文件的过程 |
| 仓库 | 仓库 | 项目库、代码库 | GitHub repository |
| 拉取请求 | PR | 合并请求、pull request | 首次出现写全，之后用 PR |

规则只有一条：**同一个概念在全站只用一种说法**，并且首次出现时给出定义。

## 二、该翻译的与不该翻译的

| 类型 | 处理 | 示例 |
| --- | --- | --- |
| 通用技术名词 | 翻译 | 依赖、构建、部署、路由 |
| 产品/项目名 | 保留原文 | VitePress、Vite、pnpm |
| 已成习惯的缩写 | 保留原文 | API、CLI、HTTP、JSON |
| 有官方中文名的 | 用官方中文 | 拉取请求、议题 |
| 无共识译法的 | 保留原文 + 括注 | token（访问令牌） |

::: warning 不要硬翻
`repository` 翻成"资料库"、`commit` 翻成"承诺"，读者反而看不懂。
这类词业界没有共识译法时，保留英文更专业。
:::

## 三、大小写规范

这是中文文档里错误率最高的地方：

| 正确 | 常见错误 |
| --- | --- |
| GitHub | Github、github |
| JavaScript | Javascript、Javascript |
| TypeScript | Typescript |
| Node.js | Nodejs、NodeJS |
| npm | NPM |
| pnpm | PNPM |
| macOS | MacOS、Mac OS |
| iOS | IOS |
| Web | web（作名词时） |

命令行、包名、文件名保持原文精确：

```bash
pnpm add vitepress    # 包名全小写
```

## 四、避免口语化与网络用语

| 不推荐 | 推荐 |
| --- | --- |
| 这个功能贼好用 | 该功能可减少约 60% 的手工操作 |
| 直接起飞 | 构建耗时从 30 秒降到 3 秒 |
| 无脑冲 | 满足上述条件时可直接使用 |
| 坑 | 已知问题 / 注意事项 |
| 白嫖 | 免费使用 |

技术文档面向的是"未来的自己"和"不认识你的同事"，语气应当中性、可长期成立。

## 五、人称与主语

- 用"你"称呼读者，不用"您"（过于正式）也不用"我们"（指代不清）
- 描述自己的操作时用"你"，描述程序行为时用"项目名"或"该命令"

| 写法 | 评价 |
| --- | --- |
| 你需要先安装依赖 | ✅ |
| 您需要先安装依赖 | ⚠️ 过于正式，中文开源文档一般不用 |
| 我们需要先安装依赖 | ❌ 主语不清，谁？ |
| 先安装依赖 | ✅ 最简洁，命令类文档首选 |

## 六、时态与语态

中文没有时态变化，但要注意**不要直译英文被动语态**：

| 英文式中文 | 自然中文 |
| --- | --- |
| 该文件被读取后 | 读取该文件后 |
| 配置被应用于所有页面 | 配置对所有页面生效 |
| 错误将会被抛出 | 程序会抛出错误 |

## 七、数字与版本号

```md
✅ VitePress 1.6.4 修复了该问题
✅ Node.js 18 及以上
❌ vitepress 1.6.4 修复了该问题    （产品名大小写错误）
❌ Node.js 18+                      （中文文档里用"及以上"更清楚）
```

## 八、链接文字

不要写"点击这里"、"详见此处"：

```md
✅ 安装步骤见 [部署到 GitHub Pages](./deployment)。
❌ 部署步骤点击这里。
```

原因：屏幕阅读器会把链接文字单独读出来，"点击这里"没有任何信息量。

## 九、维护术语一致性

人工检查靠不住，建议加个脚本扫一遍全站：

```bash
# 找出疑似错误的大小写（在项目根目录执行）
grep -rn -E "\b(Github|Javascript|Nodejs|NPM|MacOS)\b" docs/ --include="*.md"
```

把这条命令加进 CI，就能长期保持术语统一。

## 十、术语表自检

- [ ] 每个核心概念只有一种叫法
- [ ] 保留了不该硬翻的英文术语
- [ ] 产品名大小写全部正确
- [ ] 没有口语化、网络用语
- [ ] 没有直译的被动语态
- [ ] 链接文字有实际含义
