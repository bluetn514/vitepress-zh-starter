# 简介

> **这是模板的示例内容。** 下面的"项目名"是占位符，
> 换成你自己的项目信息即可。本页结构本身可以直接沿用——
> 它对应的是读者最需要先搞清楚的三个问题：这是什么、为什么用、下一步做什么。

> 这一页是"给读者的第一篇文档"。读者看完它应该能回答三个问题：
> **这是什么**、**为什么要用**、**下一步做什么**。
> 写不出这三点的项目，缺的不是文档模板，是定位。

## 项目名是什么

用一到三句话描述。避免"一个强大的、易用的、现代化的 XXX 解决方案"这类
同义堆砌——读者看完不知道它到底能干什么。

**反例**：

> 项目名是一个强大、灵活、高性能的现代化工具。

**正例**：

> 项目名把 Markdown 表格转换成可交互的 HTML 表格，
> 支持排序、筛选和导出 Excel，体积不到 10 KB。

区别在于：正例里有输入、输出、能力边界和可验证的数字。

## 为什么用项目名

对比同类方案，说清差异。表格比段落更有效：

| 场景 | 项目名 | 同类方案 A | 同类方案 B |
| --- | --- | --- | --- |
| 安装体积 | 10 KB | 2 MB | 800 KB |
| 中文文档 | 完整 | 仅英文 | 部分中文 |
| 是否需要服务端 | 不需要 | 需要 | 不需要 |
| 浏览器支持 | 现代浏览器 | IE 11+ | 现代浏览器 |

::: tip 写作建议
表格里只放**能被验证的事实**。"更好用""更优雅"这种判断留给读者自己下。
:::

## 三十秒示例

给一段最短的可运行代码。读者复制粘贴就能看到效果，这比看十段说明都管用。

```bash
# 安装
pnpm add 项目名

# 运行
npx 项目名 --input example.md
```

```js
import { convert } from '项目名'

const html = convert('# 标题\n\n正文内容')
console.log(html)
```

## 能力边界

把**不做什么**也写清楚。这能减少 80% 的无效 issue。

- ✅ 做：把 Markdown 转成 HTML
- ✅ 做：导出 Excel
- ❌ 不做：所见即所得编辑器
- ❌ 不做：服务端渲染
